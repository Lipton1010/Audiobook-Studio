## Acceptance baseline

### Interaction, accessibility, and visual acceptance

1. Keyboard: every navigation item, file chooser, form field, disclosure, audio control, link, button, theme control, and modal action is reachable in a sensible order. Native dialog focus stays trapped, Escape closes it, focus returns to the invoker, and polling does not steal focus.
2. Focus: every interactive element has a visible focus indicator in both themes. It must survive browser and native WebView rendering and meet 3:1 contrast against adjacent colors.
3. Contrast: normal text meets 4.5:1, large text 3:1, component boundaries and state indicators 3:1. Status is always named in text, not conveyed by color alone. Verify each token pairing used in light and dark themes with a contrast calculation.
4. Resize and scaling: no clipped content or horizontal page overflow at the native minimum 900 by 600, 1280 by 860 default, 1920 by 1080, narrow browser widths, and 200% text zoom. Library cards, job actions, progress, logs, and configuration reflow rather than disappear.
5. Feedback: loading names the resource; empty states explain the next action; errors identify what failed and offer recovery where possible; disabled and busy states remain readable and are announced.
6. Motion: no perpetual decorative animation. Progress motion, if any, respects `prefers-reduced-motion`.
7. Privacy: screenshots and fixtures contain only synthetic titles, paths, voice names, logs, and audio. No purchased text, private voice sample, or generated audiobook content appears in evidence.
8. Visual quality: the primary next action is clear on each screen, advanced settings use sensible disclosure, yellow is restrained, typography remains comfortable for long desktop sessions, and repeated cards reflect information hierarchy rather than decorative uniformity.

### Regression and release gates

- Run `python -m unittest discover -s tests -v` once after integration. Existing tests cover downloads, cache cleanup, process ownership, resumable plan identity, narration safety, ETA, GPU error handling, metadata, runtime, patch dependencies, and version consistency. They do not validate the embedded frontend.
- Exercise UI behavior against an isolated server or deterministic HTTP fixture. Do not start, cancel, resume, or delete an existing real job.
- Exercise the browser and native WebView separately where Save dialogs, external links, Explorer opening, viewport minimums, or download behavior differ.
- Refresh Graft after meaningful source changes and run `graft check`; separately update and review the UI dependency map because `app/static/index.html` is excluded from Graft.
- Before installer verification, require clean `HEAD`, a satisfied `RELEASE_CHECKLIST.md`, the canonical `install\build_installer.bat`, matching version evidence, and exactly the current full installer and patch executables at the top of `Output`.
- Verify Google Drive handoff against `install/BETA_HANDOFF.md`: new versioned filenames, superseded Audiobook Studio installers archived under `Old, do not use`, and no publication beyond the authorized beta folder.

## Integrated findings for correction

1. **Resolved: responsive navigation and theme access.** At 563 CSS px, `.nav` now measures 508 px client and scroll width with three equal columns, and a compact Light/Dark switch remains visible. With eight job cards at 1440 by 900, the desktop sidebar remains sticky at 900 px high and keeps the theme switch in the viewport.
2. **Resolved: empty log feedback.** **Show log** now reveals “No log entries are available yet,” exposes that message in the accessibility tree, and retains focus across polling.
3. **Resolved: zero-total narration copy.** The render path omits the chunk fraction when total is zero. The current live fixture reports 0 of 160 and therefore truthfully includes its denominator.
4. **Resolved: progress-track contrast.** Both themes now render a 1 px `--control-line` border around the track, including at zero percent.
5. **Resolved: decorative voice mark.** The visual mark no longer appears as duplicate text in the accessibility tree.
6. **Expanded synthetic state coverage.** Queued, extracting at 30%, tagging, failed, interrupted, canceled, completed-summary, narration startup, and active narration are rendered with clear named status and available actions. Active narration reports 73 of 160 chunks, 46% progress, about 14 minutes remaining, and `generating (1 worker)`.
7. **Remaining fixture boundaries.** No library book/job dialog, completed output/player/cache actions, long log, ffmpeg/update failure, import failure, uploaded-voice deletion, or downloadable report/audio file is available. These remain explicitly unexercised.
8. **Native shell and downloads passed.** The ordinary development interpreters lack `webview`, so the lead supplied the pinned pywebview bundle under the isolated review directory. The native launcher safely attached to port 8877 and rendered the dark theme correctly at 144 DPI at default and minimum window sizes. On a fresh run, actual OS Page Down input exposed the synthetic completed job, then DPI-aware real mouse input activated its visible beta-report and WAV anchors. Each opened a foreground **Save As** window. Both dialogs were canceled without saving, and the exact native process was closed. The earlier `msedge.exe - Application Error` breakpoint `0x80000003` did not recur; retain it as a transient host/runtime observation rather than a product failure.

### Bounded native-download investigation

- The disposable bundle is the pinned `pywebview==5.4` from `install/requirements-base.txt` and loaded from `Output/ui-review/native-site`.
- `app/launcher.py:_enable_webview_downloads` sets `webview.settings["ALLOW_DOWNLOADS"] = True` before `create_window`; `tests/test_downloads.py` directly verifies that setting.
- `monitorDownload()` preserves the real anchor as the original user gesture and performs only a parallel HEAD request for feedback. The current synthetic beta-report endpoint answered `200` with `Content-Type: application/zip`, and the browser harness recorded **Beta report download starts**.
- `CLAUDE.md` records an earlier native run with this exact pywebview 5.4 package in which beta-report and WAV anchors opened Save dialogs and the saved bytes were verified. That establishes the handler path independently of this pass, though it is not evidence for the new installer.
- No `launcher_log.txt` was written by the interactive attached-server run, and the external Edge breakpoint was not captured by launcher logging. A fresh run did not reproduce the breakpoint. The original click harness was DPI unaware on a 144 DPI display, so its physical coordinate missed the anchor and could not test the handler. A corrected DPI-aware harness used real mouse input on the visible controls and confirmed both Save dialogs. No production change is warranted from the transient breakpoint.
