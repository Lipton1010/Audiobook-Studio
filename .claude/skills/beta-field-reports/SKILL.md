(V, 2026-08-02) TRAP FOR ANY NON-WINDOWS TOOLING. The working-tree files are CRLF while the HEAD blobs are LF, which Windows git reconciles through `core.autocrlf`. A git run from a Linux shell or container with `core.autocrlf` unset reports ALL 31 tracked files as modified and `git diff --check` fails with trailing whitespace on every added line. That is a line-ending artifact, not a regression; `git diff --ignore-cr-at-eol` shows the real four-file change set. The dangerous consequence is the write side: `git add -A`, `git commit -a`, `git stash` or `git checkout` from such a shell would commit CRLF into all 31 files. Do git writes on Windows only.
